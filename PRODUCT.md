# TabDock — Product Definition

## 1. Идея продукта

TabDock — диспетчер браузерного пространства для открытых вкладок, постоянных ссылок и рабочих наборов.

Пользователь организует браузер не вокруг десятков постоянно открытых вкладок, а вокруг понятных разделов первого уровня.

Пример:

- Работа 1
- Работа 2
- Ежемесячные оплаты
- YouTube
- Погода
- Книги
- Музыка
- Бюджет
- Калории
- Временное

Внутри каждого раздела находятся ссылки с названием и favicon.

TabDock знает, какие из этих страниц уже открыты, позволяет переключиться на них, открыть закрытые или открыть весь раздел целиком.

---

## 2. Проблема

Обычный браузер смешивает несколько разных сущностей:

1. страницы, которые нужны прямо сейчас;
2. страницы, которые нужны постоянно;
3. рабочие наборы из нескольких связанных страниц;
4. страницы, которые понадобятся когда-нибудь позже;
5. обычные закладки.

Из-за этого пользователь вынужден держать десятки вкладок открытыми просто потому, что иначе потом трудно вспомнить:

- что именно было сохранено;
- где это искать;
- зачем эта страница вообще была нужна.

Поиск сам по себе проблему не решает:

> чтобы найти страницу через неделю, сначала нужно помнить, что её вообще надо искать.

TabDock должен заменить необходимость помнить конкретные вкладки структурой, которую пользователь видит постоянно.

---

## 3. Основная ценность

TabDock должен позволять держать открытыми только те вкладки, которые действительно нужны сейчас, не теряя быстрый доступ ко всему остальному.

Основные преимущества:

- меньше постоянно открытых вкладок;
- постоянные ссылки находятся в понятной структуре;
- рабочий набор открывается одной кнопкой;
- видно, какие страницы уже открыты;
- переход к существующей вкладке вместо создания дубля;
- временную страницу можно сохранить и закрыть;
- не нужно помнить точное название страницы для поиска;
- рабочий контекст можно открыть утром и закрыть вечером без потери его структуры.

---

## 4. Core Loop

Основной цикл использования TabDock:

1. Пользователь открывает TabDock.
2. Видит дерево своих разделов.
3. Выбирает нужный раздел.
4. Открывает одну страницу или весь набор.
5. Работает с вкладками в браузере.
6. TabDock показывает их состояние как открытые.
7. Ненужные сейчас вкладки можно закрыть или сохранить во «Временное».
8. Позже пользователь возвращается к разделу и восстанавливает нужный контекст.

Ключевой принцип:

> структура хранится независимо от того, открыты вкладки сейчас или нет.

---

## 5. Основная модель данных

### Section

Раздел первого уровня.

Примеры:

- Работа 1
- Работа 2
- Книги
- Музыка
- Оплаты
- Бюджет

Свойства:

- id
- название
- иконка / emoji
- порядок
- свёрнут / развёрнут
- список сохранённых ссылок

Специальные системные разделы могут существовать отдельно:

- Временное
- Открытые без раздела

---

### Link

Сохранённая страница.

Свойства:

- URL
- favicon
- название страницы
- пользовательское название
- sectionId
- порядок внутри раздела
- дата добавления
- дата последнего открытия

Runtime-состояние:

- открыта сейчас / закрыта;
- tabId открытой вкладки;
- windowId;
- позиция вкладки.

Runtime-состояние не является частью постоянной структуры.

---

## 6. Разделы вместо папок

В первой версии используется только один уровень:

```
Section
└── Link
```

Не должно быть:

```
Работа
└── Проекты
    └── Проект 1
        └── Прод
            └── Админка
```

TabDock должен оставаться визуально простым.

Если структура начинает требовать несколько уровней вложенности — сначала нужно проверить, действительно ли это необходимо.

---

## 7. Рабочие наборы

Любой раздел может использоваться как рабочий набор.

Например:

### Работа 2

1. Front сайта
2. Админка
3. GitLab
4. Bitrix
5. Документация
6. Статистика
7. Тестовый сайт
8. Почта

Пользователь нажимает:

> Открыть всё

TabDock открывает все закрытые страницы раздела.

Если часть страниц уже открыта:

- дубли не создаются;
- существующие вкладки используются;
- недостающие открываются.

Вкладки должны открываться рядом и в порядке, заданном внутри раздела.

Состав рабочего набора существует независимо от состояния браузера.

Закрытие вкладки не удаляет её из рабочего набора.

---

## 8. Состояние вкладок

TabDock должен визуально показывать состояние каждой ссылки.

Пример:

```
Работа 2                         6 / 8

● Front
● Admin
● GitLab
● Bitrix
○ API documentation
● Statistics
○ Test
● Mail
```

Где:

- ● — страница уже открыта;
- ○ — сохранена, но сейчас закрыта.

Действия:

- клик по ● → переключиться на существующую вкладку;
- клик по ○ → открыть страницу.

Главный принцип:

> если URL уже открыт, TabDock не должен без необходимости создавать его второй экземпляр.

---

## 9. Основной интерфейс

Основной интерфейс TabDock должен быть достаточно удобным, чтобы пользователь мог держать его открытым в течение рабочего дня.

Это не должен быть маленький popup только для редких действий.

Предпочтительная модель:

- постоянная боковая панель;
- сверху поиск;
- ниже дерево разделов;
- разделы можно сворачивать;
- favicon у каждой страницы;
- состояние open / closed видно сразу.

Пример:

```
┌────────────────────────────────┐
│ 🔎 Поиск                       │
├────────────────────────────────┤
│                                │
│ 💼 Работа 1              5 / 7 │
│   ● Админка                    │
│   ● Сайт                       │
│   ○ Документация               │
│                                │
│ 💼 Работа 2              8 / 8 │
│   ● Front                      │
│   ● Admin                      │
│   ● GitLab                     │
│                                │
│ 💳 Ежемесячные оплаты          │
│ 🎬 YouTube                     │
│ ☁️ Погода                     │
│ 📚 Книги                       │
│ 🎵 Музыка                     │
│ 💰 Бюджет                     │
│ ⚖️ Калории                    │
│                                │
│ 📥 Временное              (12) │
└────────────────────────────────┘
```

---

## 10. Работа с разделом

Раздел должен поддерживать:

- открыть / закрыть;
- переименовать;
- изменить иконку;
- изменить порядок;
- удалить;
- открыть все ссылки;
- закрыть открытые вкладки раздела;
- добавить текущую вкладку;
- drag & drop ссылок.

Количество открытых страниц показывается рядом:

`Работа 2 — 6 / 8`

---

## 11. Работа со ссылкой

Для каждой ссылки:

Основное действие:

- открыть;
- если уже открыта — переключиться на неё.

Дополнительные:

- переименовать;
- изменить URL;
- переместить в другой раздел;
- удалить из TabDock;
- открыть отдельную копию;
- закрыть открытую вкладку.

Удаление ссылки из TabDock и закрытие вкладки — разные действия.

---

## 12. Добавление текущей вкладки

Текущую страницу можно быстро:

### Добавить в раздел

Страница сохраняется, но остаётся открытой.

### Сохранить и закрыть

Страница сохраняется в выбранный раздел, после чего вкладка закрывается.

### Отложить

Страница сохраняется во «Временное» и закрывается.

Эта операция должна занимать минимальное количество действий.

---

## 13. Временное

«Временное» — системный раздел для страниц, место которых пока неизвестно.

Примеры:

- статья;
- товар;
- документация;
- интересный сайт;
- материал «посмотреть потом».

Пользователь не обязан сразу придумывать категорию.

Позже ссылку можно:

- открыть;
- удалить;
- перетащить в постоянный раздел.

Главная задача «Временного»:

> позволить спокойно закрыть вкладку, не принимая решение о её дальнейшей судьбе прямо сейчас.

---

## 14. Открытые вкладки без раздела

TabDock должен видеть открытые вкладки браузера, даже если они ещё не сохранены в структуре.

Такие страницы могут отображаться отдельно:

### Открытые без раздела

Отсюда пользователь может:

- перейти к вкладке;
- добавить её в существующий раздел;
- отправить во «Временное»;
- закрыть.

Это связывает текущее состояние браузера с постоянной структурой TabDock.

---

## 15. Поиск

Поиск является дополнительным способом навигации, но не заменяет дерево разделов.

Поиск выполняется одновременно по:

- пользовательскому названию;
- title страницы;
- URL;
- домену;
- названию раздела.

Результат должен показывать состояние:

- ● открыта
- ○ сохранена

Если страница открыта — результат переводит пользователя на неё.
Если закрыта — открывает.

Поиск также должен находить открытые вкладки, которые ещё не сохранены в TabDock.

---

## 16. Drag & Drop

Drag & Drop — один из основных способов организации.

Пользователь должен иметь возможность:

- менять порядок разделов;
- менять порядок ссылок;
- переносить ссылку между разделами;
- переносить временную ссылку в постоянный раздел;
- добавлять открытую вкладку в раздел.

Организация структуры должна ощущаться как работа с обычным деревом, а не как заполнение формы.

---

## 17. Favicon и визуальная идентификация

Для ссылок используются favicon сайтов.

Название может быть изменено пользователем.

Например:

Оригинальный title:

> Dashboard | Production system | Example Corp

Пользователь может назвать:

> Админка

В интерфейсе:

`⚙️ Админка`

Это важнее полного технического title страницы.

---

## 18. Отношение к Chrome Tab Groups

Chrome Tab Groups не являются моделью данных TabDock.

Источник истины:

> структура TabDock.

Нативные группы браузера могут использоваться технически для удобного расположения открытых вкладок, но пользователь не должен быть обязан вручную поддерживать одновременно:

- структуру TabDock;
- структуру Chrome Groups.

TabDock потенциально должен позволить отказаться от постоянного использования стандартных групп браузера.

Если нативные группы помогают держать вкладки рабочего раздела рядом — TabDock может автоматически использовать их как технический механизм.

---

## 19. Конфиденциальность при демонстрации экрана

Одна из задач существующей структуры вкладок — не показывать личные страницы во время демонстрации рабочего экрана.

TabDock не должен ухудшать этот сценарий.

Необходимо предусмотреть простой режим, при котором часть разделов скрывается.

Рабочий пример:

VISIBLE:

- Работа 1
- Работа 2

HIDDEN:

- Книги
- YouTube
- Бюджет
- Калории
- Личное

Поиск в таком режиме также не должен показывать содержимое скрытых разделов.

Конкретный UX этого режима определяется отдельно.

---

## 20. Защита от дублей

Перед открытием сохранённой страницы TabDock проверяет открытые вкладки.

Если соответствующая страница уже существует:

→ переключиться на неё.

Если нет:

→ открыть новую.

Пользователь должен иметь отдельное явное действие:

> Открыть ещё одну копию

если дубликат действительно нужен.

Нормализация URL требует отдельного проектирования:

- fragment;
- query parameters;
- trailing slash;
- SPA routes.

На MVP нельзя слишком агрессивно считать разные URL одинаковыми.

---

## 21. Сохранность данных

Структура TabDock должна храниться независимо от состояния открытых вкладок браузера.

Закрытие Chrome не должно уничтожать:

- разделы;
- ссылки;
- пользовательские названия;
- порядок;
- настройки.

Для первой версии данные хранятся локально.

Необходимы:

- Export JSON;
- Import JSON.

Облачная синхронизация не является обязательной для MVP.

---

## 22. Что TabDock НЕ должен делать в первой версии

MVP не должен превращаться в универсальную браузерную ОС.

На первом этапе не нужны:

- аккаунты;
- собственный сервер;
- облачная синхронизация;
- AI-классификация;
- автоматическое закрытие вкладок по таймеру;
- многоуровневые папки;
- сложная система тегов;
- совместная работа;
- мобильное приложение;
- управление OpenVPN;
- сетевой роутинг;
- автоматическая категоризация сайтов.

Сначала должен идеально работать основной сценарий управления вкладками.

---

## 23. Будущие возможности

После подтверждения Core Loop могут рассматриваться:

### Sessions

Сохранение текущего состояния набора вкладок как отдельной сессии.

Например:

> Исследование NAS — 14 вкладок

---

### Network Profiles

Правило открытия сайтов через разные сетевые маршруты.

Например:

YouTube → VPN
GitLab → Direct
ChatGPT → Auto

Это отдельная техническая подсистема и не относится к MVP TabDock.

---

### Notes

К ссылке можно добавить комментарий.

Например:

> инструкция по импорту торговых предложений

Поиск учитывает заметку.

---

### Aliases

Несколько поисковых названий для одной ссылки.

---

### Sync

Синхронизация структуры между компьютерами.

---

### Automatic suggestions

TabDock может предлагать сохранить часто используемые открытые вкладки.

Только после того, как ручная модель доказала свою полезность.

---

## 24. MVP Success Scenario

Исходное состояние:

В Chrome открыто около 50 вкладок.

После настройки TabDock пользователь создаёт:

- Работа 1;
- Работа 2;
- Оплаты;
- YouTube;
- Погода;
- Книги;
- Музыка;
- Бюджет;
- Калории.

Большинство ссылок больше не нужно постоянно держать открытыми.

Утром пользователь нажимает:

> Работа 2 → Открыть всё

Открываются необходимые рабочие страницы в правильном порядке.

TabDock показывает:

`Работа 2 — 8 / 8`

Во время работы:

- клик по открытой ссылке переключает на вкладку;
- закрытие вкладки меняет её статус на ○;
- клик по ○ снова её открывает;
- новая временная страница отправляется во «Временное».

Вечером рабочие вкладки можно закрыть.

На следующий день структура рабочего пространства остаётся неизменной.

Если этот сценарий удобнее постоянного хранения десятков открытых вкладок и стандартных Chrome Groups — Core Loop TabDock работает.

---

## 25. Главные продуктовые принципы

### Структура важнее поиска

Пользователь не должен помнить, что именно нужно искать.

---

### Сохранённая ссылка и открытая вкладка — не одно и то же

Открытость страницы является временным состоянием.

---

### Один уровень лучше сложного дерева

Структура должна оставаться обозримой.

---

### Никакой магии без запроса

TabDock не закрывает и не перемещает вкладки самостоятельно.

---

### Не создавать дубль без причины

Если нужная страница уже открыта — использовать её.

---

### Рабочее пространство должно подниматься одним действием

«Открыть всё» — одна из центральных функций продукта.

---

### TabDock должен уменьшать визуальный шум, а не создавать новый

Интерфейс должен быть компактным, быстрым и визуально спокойным.
